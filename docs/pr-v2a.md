## 契约不变 → 渲染层零改动

段内 diff 从 difflib 换成自研词级 LCS，渲染层一行代码没改。原因是 v1 就把
inline 的对外契约定成了块状 opcodes（equal / delete / insert），换算法只影响
这些块的切分粒度，不影响块的结构。快照测试零变化：纯中文就近删除
（"新鲜烘焙"→"新"）时，字符级 LCS 和词级 LCS 的输出字节级一致——这实证了
"中文逐字的 LCS 结果在视觉上已经接近词级"，词级真正的收益出现在拉丁文本
（function→functions 整词替换）和跨词边界的部分匹配上，这两类都有显式测试覆盖。

## 两级细化的规模收益

词级 LCS 是 O(mn) 时间与空间。2000 字的段落直接跑需要 400 万格 dp 表，先按句
对齐（句子级 LCS）再对每对句子跑词级 LCS，降到 200×200 加若干句内小表，
实测 0.02s。全文无句界时句级路径无解，退回 difflib 兜底——"没救"的输入
也不许卡死。往返不变量（equal+delete 拼回旧文本、equal+insert 拼回新文本）
覆盖三条路径，丢字 / 错序类 bug 谁也逃不掉。

## 分词零依赖

词级 LCS 需要分词，但坚持不引 jieba：零依赖是写进 README 的卖点，为一个
次要体验牺牲主要卖点不划算。自研规则分词器（CJK 逐字 + 拉丁成词 + 标点切分）
只有几十行，两个坑写成回归测试：`isalnum()` 对汉字返回 True（会把无空格的
"函数"吞成一个 token），全角字母数字同样被命中——靠"先判 CJK 再判 isalnum"
的顺序挡住。
